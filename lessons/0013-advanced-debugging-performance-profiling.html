Lesson 0013: Advanced Debugging & Performance Profiling

Threading models (JS Thread vs UI Thread), React DevTools, eliminating re-renders, and memory profiling

1. The Mobile Threading Architecture (JS Thread vs. UI Thread)

In Angular web applications, all JavaScript, DOM updates, and style calculations run on the single browser main thread. React Native splits work across two primary threads:

Thread Responsibilities What Happens if Blocked?
JavaScript Thread Business logic, React rendering, API calls, state updates. Touch events lag, async data is delayed, but animations can still run smoothly on UI thread.
UI (Native) Thread Native layout, rendering pixels, gesture handling, native drivers. App stutters, drops frames below 60 FPS, feels "frozen".

2. Essential Debugging Toolkit for React Native

Moving beyond standard console.log():

  • Expo Dev Menu (Cmd+D on iOS / Cmd+M on Android): Fast reload, toggle element inspector, toggle performance monitor (FPS counter).
  • Metro Bundler Terminal: Real-time bundle errors, compile-time warnings, stack traces with sourcemaps.
  • React DevTools Profiler: Visualize component render durations and inspect flame graphs to spot components rendering unnecessarily.
  • Chrome DevTools MCP / Remote Debugger: Inspect network requests, memory heap snapshots, and break on exceptions.

3. Eliminating Re-renders (`React.memo`, `useCallback`, `useMemo`)

In Angular, ChangeDetectionStrategy.OnPush prevents re-checking unmodified components. In React Native, combine React.memo with memoized callback handlers:

import React, { memo, useCallback, useState, useMemo } from 'react';
import { View, Text, TouchableOpacity, StyleSheet } from 'react-native';

// 1. Memoized child component (Equivalent to Angular OnPush)
const PostCard = memo(function PostCard({
  post,
  onLike,
}: {
  post: { id: string; title: string };
  onLike: (id: string) => void;
}) {
  console.log('Rendering PostCard:', post.id);
  return (
    <View style={styles.card}>
      <Text style={styles.title}>{post.title}</Text>
      <TouchableOpacity onPress={() => onLike(post.id)}>
        <Text style={styles.like}>❤️ Like</Text>
      </TouchableOpacity>
    </View>
  );
});

export default function FeedContainer({ initialPosts }: { initialPosts: any[] }) {
  const [posts, setPosts] = useState(initialPosts);

  // 2. Stable callback reference (prevents re-rendering PostCard children)
  const handleLike = useCallback((id: string) => {
    setPosts((prev) =>
      prev.map((p) => (p.id === id ? { ...p, likes: (p.likes || 0) + 1 } : p))
    );
  }, []);

  return (
    <View style={styles.container}>
      {posts.map((post) => (
        <PostCard key={post.id} post={post} onLike={handleLike} />
      ))}
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 16 },
  card: { padding: 12, backgroundColor: '#fff', marginBottom: 8, borderRadius: 8 },
  title: { fontSize: 16, fontWeight: 'bold' },
  like: { color: '#FF2D55', marginTop: 8 }
});

4. FlatList Performance Tuning

For feeds with hundreds of images (like BeReal), tune these key props:

<FlatList
  data={posts}
  keyExtractor={(item) => item.id}
  renderItem={renderItem}
  initialNumToRender={5}     // Render only enough items to fill initial screen
  maxToRenderPerBatch={5}    // Control batch size per scroll increment
  windowSize={5}             // Reduce offscreen render buffer to conserve RAM
  removeClippedSubviews={true} // Unmount views outside current viewport
/>
