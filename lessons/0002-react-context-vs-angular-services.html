Lesson 0002: React Context vs. Angular Services

Dissecting AuthContext.tsx and _layout.tsx from your BeReal codebase

1. The Direct Code Comparison

Here is how your AuthContext.tsx matches what you would build in Angular:

Angular Pattern Your BeReal AuthContext.tsx What Happens Under the Hood
@Injectable({ providedIn: 'root' }) const AuthContext = createContext(...) Creates a memory container for shared state across the component tree.
app.config.ts providers <AuthProvider>{children}</AuthProvider> Wraps root layout in src/app/_layout.tsx so all child routes can access auth data.
private user$ = new BehaviorSubject(null); const [user, setUser] = useState<User | null>(null); Component-level state hook holding the active profile object.
constructor(private auth: AuthService) / inject() const { user, signUp } = useAuth(); Custom Hook that reads from the nearest AuthContext.Provider ancestor.
CanActivate Route Guard useEffect(() => { router.replace(...) }, [user]) Declarative route redirection based on reactive state changes.

2. Key Insight: React Re-rendering vs. Angular Zone/Signals

In Angular, changing a BehaviorSubject notifies subscribers (or Signals trigger fine-grained DOM updates). In React:

  • When setUser(profile) is called in signUp(), React marks AuthProvider as dirty.
  • React re-evaluates AuthProvider and passes the new value={{ user, signUp, updateUser }} object down.
  • Any component calling useAuth() receives the new user object and automatically re-renders with fresh data.

3. Debugging Auth State & Navigation

Quick Debug Technique: Add a temporary useEffect inside AuthProvider to log state changes: 
useEffect(() => {
  console.log("🔒 Auth state updated:", user?.email || "Logged out");
}, [user]);
This logs instantly in your Metro terminal when Supabase completes login or signup.
