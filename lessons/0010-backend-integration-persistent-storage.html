Lesson 0010: Backend Integration & Persistent Storage

Supabase integration, local storage mechanics (AsyncStorage vs MMKV), and session hydration vs Angular HttpInterceptor

1. Web `localStorage` vs. Mobile Persistent Storage

In Angular web applications, developers frequently use browser localStorage (synchronous, strings only, ~5MB limit). In mobile development, filesystem access must run off the JavaScript thread to prevent UI freezing:

Feature Web localStorage React Native AsyncStorage react-native-mmkv (Modern)
API Type Synchronous Asynchronous (Promise-based) Synchronous (via C++ JSI)
Performance Fast on web Bridge-serialized, medium Extremely fast (~30x AsyncStorage)
Underlying Engine Browser storage SQLite (Android) / Files (iOS) Memory-mapped binary files (MMKV)
Use Case Web app tokens & preferences Universal standard, Supabase storage High-throughput caching, offline state

2. Configuring the Supabase Mobile Client

In Angular, attaching auth tokens across requests typically requires an HttpInterceptor. With the Supabase JS client in React Native, you provide a storage adapter so auth sessions are automatically persisted, restored, and refreshed:

// src/lib/supabase/client.ts
import 'react-native-url-polyfill/auto';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { createClient } from '@supabase/supabase-js';

const SUPABASE_URL = process.env.EXPO_PUBLIC_SUPABASE_URL || 'https://xyz.supabase.co';
const SUPABASE_ANON_KEY = process.env.EXPO_PUBLIC_SUPABASE_ANON_KEY || 'public-anon-key';

export const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY, {
  auth: {
    storage: AsyncStorage,
    autoRefreshToken: true,
    persistSession: true,
    detectSessionInUrl: false, // Disabled for native mobile environments
  },
});

3. Session Hydration & Bootstrapping in `AuthContext`

Because native storage is asynchronous, mobile apps require a Session Hydration phase during app launch before executing route guards:

// src/context/AuthContext.tsx
import React, { createContext, useContext, useEffect, useState } from 'react';
import { Session, User } from '@supabase/supabase-js';
import { supabase } from '../lib/supabase/client';

interface AuthContextType {
  user: User | null;
  session: Session | null;
  isLoading: boolean;
  signOut: () => Promise<void>;
}

const AuthContext = createContext<AuthContextType>({
  user: null,
  session: null,
  isLoading: true,
  signOut: async () => {},
});

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [session, setSession] = useState<Session | null>(null);
  const [isLoading, setIsLoading] = useState<boolean>(true);

  useEffect(() => {
    // 1. Initial Session Hydration from AsyncStorage
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session);
      setIsLoading(false);
    });

    // 2. Listen for Auth State Changes (Login, Logout, Token Refresh)
    const { data: { subscription } } = supabase.auth.onAuthStateChange((_event, session) => {
      setSession(session);
      setIsLoading(false);
    });

    return () => {
      subscription.unsubscribe();
    };
  }, []);

  const signOut = async () => {
    await supabase.auth.signOut();
  };

  return (
    <AuthContext.Provider value={{ user: session?.user ?? null, session, isLoading, signOut }}>
      {children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => useContext(AuthContext);

4. Key Takeaways for Angular Leads

  • No Manual Interceptors: Supabase handles token rotation, authorization header attachment, and refresh triggers under the hood through the configured storage engine.
  • Always Guard Against Unhydrated State: Ensure root routing layouts (e.g. src/app/_layout.tsx) check isLoading before redirecting unauthenticated users to avoid flashing the login screen on app boot.
  • Async Storage is Promise-based: Whenever reading or writing directly with AsyncStorage.getItem() / setItem(), always use await or Promise chains.
