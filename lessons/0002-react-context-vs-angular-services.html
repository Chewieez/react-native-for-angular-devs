Lesson 0002: React Context vs. Angular Services

Architecting global state, custom hooks, and route guarding in React Native & Expo Router

1. The Dependency Injection & State Translation

In Angular, singleton services decorated with @Injectable({ providedIn: 'root' }) hold shared state (often using BehaviorSubject or Signals) and inject dependencies across the app via constructor or inject(). React achieves the exact same architectural capability using React Context and Custom Hooks.

Angular Pattern React Native & Expo Equivalent Execution & Architecture Under the Hood
@Injectable({ providedIn: 'root' }) const AuthContext = createContext(...) Creates a memory container for shared state accessible across component sub-trees.
app.config.ts root providers <AuthProvider>{children}</AuthProvider> Wraps the root layout in src/app/_layout.tsx so all child screens inherit auth state.
private user$ = new BehaviorSubject(null); const [user, setUser] = useState<User | null>(null); State hook inside Provider holding the current user profile object.
constructor(private auth: AuthService) const { user, login } = useAuth(); Custom Hook consuming Context via useContext(AuthContext).
CanActivate Route Guard useEffect(() => { router.replace(...) }, [user]) Declarative route redirection based on reactive state changes.

2. Side-by-Side Code Comparison: Authentication System

Angular Service (`auth.service.ts`)

// auth.service.ts
import { Injectable } from '@angular/core';
import { BehaviorSubject } from 'rxjs';

export interface User { id: string; email: string; }

@Injectable({ providedIn: 'root' })
export class AuthService {
  private userSubject = new BehaviorSubject<User | null>(null);
  user$ = this.userSubject.asObservable();

  async login(email: string): Promise<void> {
    const user = { id: '123', email };
    this.userSubject.next(user);
  }

  logout(): void {
    this.userSubject.next(null);
  }
}

React Native Context + Custom Hook (`AuthContext.tsx`)

// src/context/AuthContext.tsx
import React, { createContext, useContext, useState } from 'react';

export interface User { id: string; email: string; }

interface AuthContextType {
  user: User | null;
  login: (email: string) => Promise<void>;
  logout: () => void;
}

const AuthContext = createContext<AuthContextType | undefined>(undefined);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);

  const login = async (email: string) => {
    const fetchedUser = { id: '123', email };
    setUser(fetchedUser);
  };

  const logout = () => {
    setUser(null);
  };

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom Hook (Equivalent to injecting AuthService in Angular)
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within an AuthProvider');
  }
  return context;
}

3. Root Application Wrapping in Expo Router (`src/app/_layout.tsx`)

To make the Context available everywhere, wrap your root `` inside `app/_layout.tsx`:

// src/app/_layout.tsx
import { Stack } from 'expo-router';
import { AuthProvider } from '../context/AuthContext';

export default function RootLayout() {
  return (
    <AuthProvider>
      <Stack screenOptions={{ headerShown: false }}>
        <Stack.Screen name="(tabs)" />
        <Stack.Screen name="(auth)" />
      </Stack>
    </AuthProvider>
  );
}

4. Re-rendering Mechanics: React Context vs. Angular Zone.js & Signals

Understanding how updates propagate is critical for senior front-end leads:

Context Re-render Rule: When setUser(user) is called inside AuthProvider, React marks AuthProvider as dirty. React evaluates AuthProvider and passes the new value={{ user, login, logout }} reference down.

Every component calling useAuth() will re-render automatically. To prevent unnecessary re-renders in large applications, separate rapidly changing state (e.g. active form input text) from global state (e.g. user authentication object).
