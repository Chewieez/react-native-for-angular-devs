Lesson 0004: Forms & Controlled Inputs in React Native

Connecting UI Inputs to State & Auth Handlers (Angular Reactive Forms vs. Controlled Components)

1. The Angular vs. React Native Form Comparison

Angular Pattern React Native Controlled Component Key Difference
[(ngModel)]="email" value={email} onChangeText={setEmail} React uses explicit two-way binding props (value prop + onChangeText callback).
formControlName="email" Local useState hooks (or form libraries like React Hook Form) No built-in framework form module. Component state directly controls the input value.
(ngSubmit)="onLogin()" <TouchableOpacity onPress={handleLogin}> No HTML <form> element in Native. Buttons handle tap events directly via onPress.

2. Dissecting your LoginScreen (`login.tsx`)

Looking at your current login.tsx, the <TextInput> elements are un-controlled (unbound):

Unbound (Current): 
<TextInput placeholder='Email...' style={styles.input} />
Controlled (Connected): 
const [email, setEmail] = useState('');
const [password, setPassword] = useState('');
const { signIn } = useAuth();

<TextInput 
  value={email}
  onChangeText={setEmail}
  placeholder='Email...'
  keyboardType="email-address"
  autoCapitalize="none"
/>

<TouchableOpacity style={styles.button} onPress={() => signIn(email, password)}>
  <Text style={styles.buttonText}>Sign In</Text>
</TouchableOpacity>

3. Props Reference for TextInput

  • onChangeText={(text) => ...}: Fires on every keystroke with the raw string parameter (no $event.target.value wrapping needed!).
  • secureTextEntry: Boolean for password masking.
  • autoCapitalize="none": Prevents iOS from capitalizing initial letters of email/username inputs.
  • keyboardType="email-address": Displays mobile email keyboard layout with @ and .com.
