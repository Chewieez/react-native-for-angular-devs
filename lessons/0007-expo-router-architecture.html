Lesson 0007: Expo Router Architecture & File-Based Routing

Translating Angular RouterModule & Route Guards to Expo Router Managed File-Based Architecture

1. Angular RouterModule vs. Expo Router

In Angular, routes are registered via JavaScript configuration arrays in app.routes.ts. Expo Router uses file-based routing where directory paths inside src/app/ map directly to application routes, powered by React Navigation under the hood.

Concept Angular (Web) React Native (Expo Router)
Route Definition Routes Array Config (app.routes.ts) File System Structure (src/app/ conventions)
Nested Screen Outlet <router-outlet> <Stack />, <Tabs />, or <Slot />
Root / Parent Layout Parent Layout Component with template outlet _layout.tsx wrapper component
Route Grouping Feature Modules / Nested child route arrays Group Segment Folders (group) (e.g. (auth), (tabs))
Dynamic Route Params Route Parameter path: 'user/:id' Dynamic Bracket File [id].tsx (via useLocalSearchParams())
Route Guarding CanActivate functional guard useEffect + router.replace() in Root Layout

2. The Layout Tree & Root Layout (_layout.tsx)

Just like an Angular App Component containing <router-outlet> and root Providers, src/app/_layout.tsx acts as the entry shell for your React Native app:

// src/app/_layout.tsx
import { Stack } from 'expo-router';
import { AuthProvider } from '../context/AuthContext';

export default function RootLayout() {
  return (
    <AuthProvider>
      <Stack screenOptions={{ headerShown: false }}>
        <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
        <Stack.Screen name="(auth)" options={{ headerShown: false }} />
        <Stack.Screen name="modal" options={{ presentation: 'modal' }} />
      </Stack>
    </AuthProvider>
  );
}

3. Declarative Route Guarding (Angular CanActivate vs. Expo Router)

In Angular, a CanActivate guard blocks route activation before rendering. In React Native, route guarding is declarative: we watch authentication state in _layout.tsx or custom hooks, redirecting unauthorized users automatically:

// Inside AuthContext or Root Layout Guard
import { useRouter, useSegments, useFocusEffect } from 'expo-router';
import { useCallback } from 'react';

export function useProtectedRoute(user: User | null, isLoading: boolean) {
  const segments = useSegments();
  const router = useRouter();

  // useFocusEffect fires every time this screen gains focus,
  // not just on mount — important for tab switches and back navigation.
  // For one-time mount-only checks, useEffect with [] also works.
  useFocusEffect(
    useCallback(() => {
      if (isLoading) return;

      const inAuthGroup = segments[0] === '(auth)';

      if (!user && !inAuthGroup) {
        // Unauthenticated: Redirect to login
        router.replace('/(auth)/login');
      } else if (user && inAuthGroup) {
        // Authenticated: Redirect to main tabs
        router.replace('/(tabs)');
      }
    }, [user, segments, isLoading])
  );
}

4. Key Advantages for Angular Developers

  • No manual route declarations: Adding a new screen is as simple as creating src/app/settings.tsx.
  • Native Transitions: Using <Stack> gives you native iOS card slide transitions and Android fade/slide transitions out-of-the-box.
  • Deep Linking Built-In: Every file route in Expo Router is automatically deep-linkable across web and mobile schemes.
  • Local vs. Global Search Params: Use useLocalSearchParams() to access query and route params scoped to the current screen (equivalent to Angular's ActivatedRoute.snapshot.params), and useGlobalSearchParams() when an outer layout needs to read params from a deeply nested route.
