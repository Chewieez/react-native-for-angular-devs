Lesson 0015: Push Notifications & Deep Linking Architecture

APNs/FCM push tokens (expo-notifications), notification handling in background/foreground, and auto-routing with Expo Router deep links

1. Web Push API vs. Native Push Architecture (APNs / FCM)

In Angular web applications, push notifications rely on browser Service Workers and the Web Push API. In mobile development, notifications must route through Apple Push Notification service (APNs) and Firebase Cloud Messaging (FCM):

Concept Angular / Web React Native / Expo
Gateway Browser Push Service (VAPID) Apple APNs (iOS) & Google FCM (Android) via Expo Push Service
Token Registration serviceWorker.pushManager.subscribe() Notifications.getExpoPushTokenAsync()
Handling When App is Closed Service Worker background event Native OS tray handling + response listener on app launch
Deep Linking Manual route parsing (e.g. /app/feed) Universal URL schemes automatically mapped to file routes in Expo Router

2. Registering for Push Notifications & Getting Push Tokens (expo-notifications & expo-device)

Mobile platforms strictly require physical device testing for APNs/FCM tokens:

// src/utils/notifications.ts
import * as Notifications from 'expo-notifications';
import * as Device from 'expo-device';
import { Platform } from 'react-native';

// Configure foreground notification presentation behavior
Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldShowAlert: true,
    shouldPlaySound: true,
    shouldSetBadge: true,
  }),
});

export async function registerForPushNotificationsAsync(): Promise<string | null> {
  if (!Device.isDevice) {
    console.log('Must use a physical device for push notifications');
    return null;
  }

  // 1. Check existing permission
  const { status: existingStatus } = await Notifications.getPermissionsAsync();
  let finalStatus = existingStatus;

  // 2. Prompt if not yet granted
  if (existingStatus !== 'granted') {
    const { status } = await Notifications.requestPermissionsAsync();
    finalStatus = status;
  }

  if (finalStatus !== 'granted') {
    alert('Failed to get push token for push notification!');
    return null;
  }

  // 3. Obtain Expo Push Token (e.g. ExponentPushToken[xxxxxxxxxxxx])
  const token = (await Notifications.getExpoPushTokenAsync({
    projectId: 'your-expo-project-id',
  })).data;

  // Android specific channel setup
  if (Platform.OS === 'android') {
    Notifications.setNotificationChannelAsync('default', {
      name: 'default',
      importance: Notifications.AndroidImportance.MAX,
      vibrationPattern: [0, 250, 250, 250],
    });
  }

  return token;
}

3. Responding to Notification Taps with Expo Router Deep Linking

When a user taps a notification (e.g. "⚠️ Time to BeReal ⚠️" or a new friend comment), navigate directly to that specific screen using router.push():

// src/hooks/useNotificationObserver.ts
import { useEffect, useRef } from 'react';
import * as Notifications from 'expo-notifications';
import { useRouter } from 'expo-router';

export function useNotificationObserver() {
  const router = useRouter();
  const notificationListener = useRef<Notifications.Subscription>();
  const responseListener = useRef<Notifications.Subscription>();

  useEffect(() => {
    // 1. Triggered when notification arrives while app is in foreground
    notificationListener.current = Notifications.addNotificationReceivedListener(notification => {
      console.log('Foreground notification:', notification);
    });

    // 2. Triggered when user TAPS on the notification
    responseListener.current = Notifications.addNotificationResponseReceivedListener(response => {
      const data = response.notification.request.content.data;
      
      // Auto-navigate to dynamic route if route param is present
      if (data?.postId) {
        router.push(`/post/${data.postId}`);
      } else if (data?.screen) {
        router.push(data.screen);
      }
    });

    return () => {
      notificationListener.current && Notifications.removeNotificationSubscription(notificationListener.current);
      responseListener.current && Notifications.removeNotificationSubscription(responseListener.current);
    };
  }, [router]);
}

4. Key Insights for Angular Leads

  • Universal Deep Linking: Expo Router makes every file in src/app/ deep-linkable. A notification payload of { screen: "/(tabs)/profile" } routes directly without manual path parsing.
  • Physical Device Requirement: iOS Simulators cannot receive standard APNs remote pushes; always test push tokens on physical hardware.
  • Expo Push Service: You can send pushes from your backend (Supabase Edge Functions / Node.js) with a simple POST to https://exp.host/--/api/v2/push/send.
