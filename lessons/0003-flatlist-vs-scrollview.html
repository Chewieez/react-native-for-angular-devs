Lesson 0003: FlatList vs. ScrollView & Data Virtualization

Translating Angular *cdkVirtualFor and *ngFor to FlatList, ScrollView, FlashList, and cell recycling

1. The Native List Rendering Dilemma

Unlike web browsers that can render hundreds of HTML DOM nodes without crashing, mobile devices operate under strict RAM and UI thread memory limits. Rendering a dynamic list using .map() inside a standard ScrollView forces native iOS and Android engines to instantiate all child views in memory at once, causing memory spikes, dropped frames, and eventual Out-Of-Memory (OOM) app crashes.

Concept ScrollView (Static List) FlatList (Virtual List)
Rendering Engine Renders all children immediately upon mount. No native view recycling. Virtualizes items. Recycles and unmounts off-screen native views.
Memory Footprint O(N) unbounded linear memory growth. Can crash with large lists. O(1) bounded memory window with constant frame rate.
Ideal Use Case Small, fixed layouts (< 20 items), settings forms or detail screens. Dynamic feeds, search results, chat messages, infinite scrolling lists.

2. Angular vs. React Native List Virtualization

Concept Angular (Web) React Native (Mobile)
List Iteration & Tracking *ngFor="let item of items; trackBy: trackById" <FlatList data={items} keyExtractor={item => item.id} />
Virtual Scroll Viewport cdk-virtual-scroll-viewport (Angular CDK) <FlatList windowSize={5} maxToRenderPerBatch={10} />
Fixed Height Optimization [itemSize]="50" getItemLayout={(data, index) => ({ length: 50, offset: 50 * index, index })}

3. Production Code Example: Virtualized Feed with Pagination & Pull-to-Refresh

import React, { useState, useCallback } from 'react';
import {
  View,
  Text,
  FlatList,
  StyleSheet,
  ActivityIndicator,
  RefreshControl,
} from 'react-native';

interface PostItem {
  id: string;
  title: string;
  author: string;
}

const INITIAL_DATA: PostItem[] = Array.from({ length: 20 }, (_, i) => ({
  id: `post-${i + 1}`,
  title: `Post Title #${i + 1}`,
  author: `User @author_${i + 1}`,
}));

export function FeedScreen() {
  const [posts, setPosts] = useState(INITIAL_DATA);
  const [isRefreshing, setIsRefreshing] = useState(false);
  const [isLoadingMore, setIsLoadingMore] = useState(false);

  // Pull-to-Refresh Handler
  const handleRefresh = useCallback(async () => {
    setIsRefreshing(true);
    // Fetch latest data from API
    await new Promise(resolve => setTimeout(resolve, 1000));
    setPosts(INITIAL_DATA);
    setIsRefreshing(false);
  }, []);

  // Infinite Scroll Pagination Handler
  const handleEndReached = useCallback(async () => {
    if (isLoadingMore) return;
    setIsLoadingMore(true);

    // Fetch next page of data
    await new Promise(resolve => setTimeout(resolve, 800));
    const nextBatch: PostItem[] = Array.from({ length: 10 }, (_, i) => ({
      id: `post-${posts.length + i + 1}`,
      title: `Post Title #${posts.length + i + 1}`,
      author: `User @author_${posts.length + i + 1}`,
    }));

    setPosts(prev => [...prev, ...nextBatch]);
    setIsLoadingMore(false);
  }, [posts.length, isLoadingMore]);

  // Render Item Callback (Keep pure or wrap in React.memo)
  const renderPost = useCallback(({ item }: { item: PostItem }) => (
    <View style={styles.card}>
      <Text style={styles.title}>{item.title}</Text>
      <Text style={styles.author}>By {item.author}</Text>
    </View>
  ), []);

  return (
    <View style={styles.container}>
      <FlatList
        data={posts}
        keyExtractor={item => item.id}
        renderItem={renderPost}
        contentContainerStyle={styles.listPadding}
        
        // Refresh & Pagination
        refreshControl={
          <RefreshControl refreshing={isRefreshing} onRefresh={handleRefresh} />
        }
        onEndReached={handleEndReached}
        onEndReachedThreshold={0.5} // Triggers when within 50% screen height of bottom
        
        // Footer Loader
        ListFooterComponent={
          isLoadingMore ? (
            <View style={styles.footerLoader}>
              <ActivityIndicator size="small" color="#007AFF" />
            </View>
          ) : null
        }
        
        // Performance Optimizations
        initialNumToRender={10}
        maxToRenderPerBatch={10}
        windowSize={5}
        removeClippedSubviews={true}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: '#f8f9fa' },
  listPadding: { padding: 16 },
  card: {
    backgroundColor: '#ffffff',
    padding: 16,
    borderRadius: 8,
    marginBottom: 12,
    borderWidth: 1,
    borderColor: '#e9ecef',
  },
  title: { fontSize: 16, fontWeight: 'bold', color: '#212529', marginBottom: 4 },
  author: { fontSize: 14, color: '#6c757d' },
  footerLoader: { paddingVertical: 16, alignItems: 'center' },
});

4. FlatList Performance Tuning Rules

  1. getItemLayout: If your list items have fixed height (e.g. 60dp), define getItemLayout={(data, index) => ({ length: 60, offset: 60 * index, index })}. This allows FlatList to bypass dynamic layout measurement entirely!
  2. Pure Component Items: Wrap item components in React.memo() or use stable renderItem callbacks to prevent re-rendering visible items during pagination.
  3. initialNumToRender: Set this to match the exact number of items visible on screen initially (e.g. 8–10 items) for fast initial mount times.
  4. High-Performance Alternative: For heavy, complex lists, consider using @shopify/flash-list, a drop-in replacement that recycles native cells for 60–120 FPS performance.
