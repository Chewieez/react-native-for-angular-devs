⚡ Pillar 2: Reactivity, Hooks, Forms & Context

Lesson 0006: React Context vs. Angular Services

Translating root @Injectable() services and dependency injection to React Context, Providers, and custom hooks

1. The Dependency Injection & State Translation

In Angular, singleton services decorated with @Injectable({ providedIn: 'root' }) hold shared state (often using BehaviorSubject or Signals) and inject dependencies across the app via constructor or inject(). React achieves the exact same architectural capability using React Context and Custom Hooks.

Concept Angular (Web) React Native (Mobile)
Global Service Container @Injectable({ providedIn: 'root' }) const AuthContext = createContext(...) (Context container)
Root Dependency Provider app.config.ts root providers <AuthProvider>{children}</AuthProvider> in _layout.tsx
Shared Reactive State private user$ = new BehaviorSubject(null); / Signals const [user, setUser] = useState<User | null>(null); in Provider
Injecting / Consuming constructor(private auth: AuthService) / inject() const { user, login } = useAuth(); (Custom Hook via useContext)
Route Guarding CanActivate functional guard useEffect(() => { router.replace(...) }, [user])

2. Side-by-Side Code Comparison: Authentication System

Angular Service (`auth.service.ts`)

// auth.service.ts
import { Injectable } from '@angular/core';
import { BehaviorSubject } from 'rxjs';

export interface User { id: string; email: string; }

@Injectable({ providedIn: 'root' })
export class AuthService {
  private userSubject = new BehaviorSubject<User | null>(null);
  user$ = this.userSubject.asObservable();

  async login(email: string): Promise<void> {
    const user = { id: '123', email };
    this.userSubject.next(user);
  }

  logout(): void {
    this.userSubject.next(null);
  }
}

React Native Context + Custom Hook (`AuthContext.tsx`)

// src/context/AuthContext.tsx
import React, { createContext, useContext, useState } from 'react';

export interface User { id: string; email: string; }

interface AuthContextType {
  user: User | null;
  login: (email: string) => Promise<void>;
  logout: () => void;
}

const AuthContext = createContext<AuthContextType | undefined>(undefined);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);

  const login = async (email: string) => {
    const fetchedUser = { id: '123', email };
    setUser(fetchedUser);
  };

  const logout = () => {
    setUser(null);
  };

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom Hook (Consumes Context)
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within an AuthProvider');
  }
  return context;
}

3. Root Application Wrapping in Expo Router (`src/app/_layout.tsx`)

To make the Context available everywhere, wrap your root `<Stack>` inside `app/_layout.tsx`:

// src/app/_layout.tsx
import { Stack } from 'expo-router';
import { AuthProvider } from '../context/AuthContext';

export default function RootLayout() {
  return (
    <AuthProvider>
      <Stack screenOptions={{ headerShown: false }}>
        <Stack.Screen name="(tabs)" />
        <Stack.Screen name="(auth)" />
      </Stack>
    </AuthProvider>
  );
}

4. Re-rendering Mechanics: React Context vs. Angular Zone.js & Signals

Understanding how updates propagate is critical for senior front-end leads:

Context Re-render Rule vs. Angular Signals:

In Angular, Signals update only the specific DOM nodes reading that signal value without re-rendering the whole component tree. In React, when setUser(user) is called inside AuthProvider, React marks AuthProvider as dirty and passes the new value reference down.

Every component calling useAuth() will re-render automatically. To prevent unnecessary sub-tree re-renders in large applications, separate rapidly changing state (e.g. text input strokes) from broad contextual state (e.g. user authentication and theme).
